# 自有域名部署规划

V1.0 保持已验收的本地单用户方式。本次将可复现源码、版本标签、依赖和检查流程存入 GitHub；不修改域名 DNS，也不把当前电脑的素材与 API Key 上传到仓库。

## 部署前需要的信息

后续提供域名/子域名、服务器系统与配置、访问范围（仅本人 / 团队 / 公开服务）、预计素材量和备份位置。域名已购买不等于已具备运行 Python 与 FFmpeg 的服务器。

## 建议落地顺序

1. 从 GitHub 的固定标签检出版本，服务器安装 Python、FFmpeg；用锁定依赖和 npm lockfile 构建。
2. 将数据置于独立持久化目录；单进程运行 SQLite 和媒体后台任务。需要多进程/多用户时先迁移任务与存储方案。
3. 为 Linux/无桌面服务器提供可恢复的密钥管理方式。当前桌面版主密钥在系统凭据管理器，不能把 Windows 的 API Key 直接搬上 Linux 使用。
4. 为服务增加访问认证。当前 V1.0 的 localhost/Origin 检查只适合本机，不是公网登录系统；域名部署不能只删除限制后直接开放所有接口。
5. 配置受控域名白名单、反向代理、HTTPS、上传体积、长任务超时与 Range 视频访问，执行域名环境端到端验收。
6. 确认 DNS 记录后，再切换域名；正式导入素材前验证数据库/文件备份与恢复。

## 域名环境验收

- HTTPS 与登录正确，未登录无法读写素材、账单、备份或 LLM 配置。
- 上传视频可回传，后台检测可恢复，视频可 seek，提交包与交付包可完整下载。
- 服务器重启后项目、文件和任务记录仍在。
- LLM 凭证加密、服务器密钥备份与更换流程可执行，日志不含密钥。
- 备份能恢复到独立目录；旧版本代码和数据变更有回退方案。

部署实施属于后续版本变更，将先在预发布环境验证，再确认 DNS 与正式切换；本文件不代表已经上线。
